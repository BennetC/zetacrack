## Original Zetamac mechanics verified from primary sources

Inspected the [original setup page](https://arithmetic.zetamac.com/) and its [served game module](https://arithmetic.zetamac.com/dist/app.js?v=2) on 2026-10-09. The latter's UTF-8 SHA-256 was `919c65c4596ce8f1f768fe603494e22db0152ea3393b4983980b7507680e0fd0`. A posted default form returns the game using that module. No derivative clone was used as authority.

| Original behavior | Verified rule |
| --- | --- |
| Defaults | All four operations enabled, 120 seconds; addition draws two independent integers from inclusive 2–100; multiplication draws 2–12 and 2–100. |
| Subtraction | Independently draw addition operands `a,b`; display `(a+b) − a`, expecting `b`. Ordinary constrained subtraction is a different distribution. |
| Division | Independently draw multiplication factors `a,b`; display `(a×b) ÷ a`, expecting `b`; zero divisors are skipped. |
| Selection/scoring | Uniform selection among enabled operation generators, independent uniform operands, repeats permitted; each accepted answer adds one. |
| Input/time | Trimmed input must equal the integer answer's string. Uses `Date.now()` and a one-second timer; the input handler has no exclusive-deadline check. Source contains no focus-loss termination. |

**Completion decision:** provide an obvious **Standard Zetamac** run with the original default question distribution and score count, using our approved monotonic/render timing, exclusive cutoff, focus-loss ending, and exact numeric input. Make these differences discoverable in a short rules disclosure. Do not claim exact original-game compatibility or externally interchangeable scores. Never silently relabel existing custom sessions as standard. The standard run is fixed/nonadaptive, 120 seconds, immediate start, no optional countdown by default. A distinct standard generator/content identity is required; existing `exact-grid-v1` replay must remain unchanged.

## Implementation defaults that resolve remaining design details

These are reasonable local Stage 1 choices authorized by the completion request, not unrequested learning-system work.

- **Entry/navigation:** default Standard view with frozen rules and a direct Start action; Custom practice retains the approved editor and its remembered state. Saved History and Graphs are reachable from setup and saved results. Do not add navigation that can accidentally abandon an active run without using its existing end behavior.
- **Selection boundary:** distinguish frozen benchmark rules from arbitrary weighted custom content. A small fixed-benchmark policy and weighted-random custom policy choose content through the same replaceable interface; uniform operand generation and session execution stay outside it. “Fixed” means fixed content eligibility/distribution, not adaptive personalization or a requirement to repeat one question. Record actual selection context/version. Keep `exact-grid-v1` + `hierarchical-shares-v1` historical replay unchanged, including PRNG consumption.
- **Standard identity:** new mode/content/generator/policy metadata distinguishes the original question rules from ordinary custom constrained subtraction. Use dedicated version identities and original independent samples. Record configuration sufficient to reconstruct those rules. Never express the reverse-addition standard distribution as the current uniform valid subtraction-pair domain.
- **Score:** accepted-question count, with raw trace inspectable; unfinished work is separate. Full standard comparison eligibility requires the fixed 120-second settings, normal timeout, known end, and no material invalid-observation warnings. Manual/focus/recovery endings are partial runs, not full benchmark scores.
- **Cohorts:** canonicalize the actual immutable content/session definition and generation/selection/measurement provenance on the backend. Display descriptive labels and permit inspecting the full original configuration. Do not merge distinct historical identities just because their preset name matches. Standard and custom remain separate even with superficially matching ranges. Duration and precision matter. Name-only changes may be recognized as same semantics only through a deliberate documented canonicalization; otherwise conservatively keep separate cohorts.
- **Graph defaults:** choose Standard cohort if it has eligible data, otherwise the most recent available cohort. Date range defaults to all local saved data. Provide score/timing history, correct-time distribution, operation/group breakdown, and session sequence; no placeholders. Histograms use explicit deterministic edges and inclusive/exclusive rules; all bins sum to eligible count. Tables expose the same data for keyboard/screen-reader use and small samples. Empty/one-point/same-value/incomplete data must render honestly. A charting library or normal scientific/data plotting technique is appropriate; illustrations are not a replacement for plots.
- **Derivation:** new backend analytics consume existing `derive_session` question records. Do not implement competing frontend timing calculations. Read a consistent SQLite snapshot for list/analytics, as exports already do. The browser may plot supplied data and format seconds only; preserve raw precision in APIs/exports.
- **History/details:** newest first, page size about 20–50, meaningful filter labels and sessions/status/date/settings. Show explicit ongoing/incomplete state and quality warnings. Session detail supports exact values, raw accepted/last input, first-input/correct/unfinished duration, original config and event disclosure, provenance, export and safe deletion. Recovered incomplete records remain visible.
- **Retention/deletion:** retain indefinitely unless the user explicitly deletes. No automatic expiration, background recovery triggered by analytics, or destructive development cleanup of normal records. Confirm deletion of one closed session and bulk closed history with the actual scope/count. Ongoing database records and held browser ownership/pending journals are protected; errors must not falsely report success. Atomic observation/session deletion; subsequent export/history/graphs agree. Presets and remembered controls are separate and remain.
- **Local architecture:** stay with current React/TypeScript + FastAPI + SQLite, additive nullable migrations and legacy-compatible reads. Preserve protected Sites starter files. Git was initialized independently during this work; preserve its baseline without resets or unsolicited commits/worktrees. No deployment. Charts use local assets, not third-party services.

## In-scope completion boundary and honest limits

Standard-content fidelity, history, all four chart surfaces, safe deletion, provenance/policy separation, and final verification cannot be replaced by export-only access, summary cards, chart placeholders, or another future-work note.
