# Run explorer and input analytics

Approved 2026-11-05: the user agreed to the full analytics proposal and explicitly requested its implementation and Orbit tracking. Task 499 in the private zetacrack project. This authorizes descriptive platform work and explicit practice tools; no evidence of cognitive causes or learning benefit is implied.

## Contract

- `run-explorer-v1` is backend-derived from the existing validated question timings. It does not change response-timing-v1, scoring or historical raw events. Invalid timing remains null; unfinished observations retain lower-bound status.
- Show per-question total, first-field-change and remaining entry time, immediate predecessor delta, a trailing five-presentation median (available valid completions only), and historical median matched on operation, answer digit count and maximum operand integer digit count. Historical baselines use only earlier eligible sessions in the exact cohort, excluding the current session.
- Splits assign completions by acceptance time in half-open 15-second windows (the last includes the observed end). For very long sessions increase width to bound output to approximately 200 windows. Partial last windows retain their actual width. No zero-time or missing observation is converted to a complete answer.
- Time breakdown partitions valid completed intervals into before input and revised/unrevised entry, retains completions with missing first input separately, retains unfinished durations, and labels remaining observed time unattributed. Revision spans include calculation and are not counterfactual time savings.
- Revisions are changes that remove or replace characters in the minimal contiguous field diff; an episode is a contiguous run of such edits. Counts describe field changes and characters, never physical keys or incorrect attempts. Completed and unfinished revision counts are distinct. No accuracy percentage is introduced.
- An edit within 600ms of a previous full-length value differing from the expected string by one character or a swapped pair can receive `possible mistype` or `possible transposition`. This is an uncalibrated descriptive heuristic; other revised input stays unknown. Partial prefixes are not incorrect answers. No causal classification or calibrated confidence is claimed.
- New input payloads carry `answer-edits-v2`, before value, best-available before/after selections and composition status, in addition to the original value/inputType. Missing browser metadata is unknown. Only arithmetic answer-field interaction is recorded; no global keylogging. Timing semantics and cohorts remain unchanged by this optional event-payload extension.
- Replay uses recorded field-change times, offers speed/scrubbing/stepping, and preserves unknown timing. Charts support keyboard activation and equivalent data tables. Selection, filters, time breakdown and profiles link to exact questions. All summaries are deterministic observations with inspectable supporting questions.
- Ghosts use other eligible exact-cohort sessions; previous uses earlier sessions, best uses maximum score, typical is the pointwise median of other trajectories. Random questions differ; no causal or difficulty-normalized comparison is claimed. Target pace is user supplied.
- Same-seed challenges use a fresh session identity, original seed/config/generator/provenance, and an explicit `replayOf` link. They are excluded from ordinary benchmarks and have distinct cohort identity. Reload/Run again retain the challenge seed and exclusion; countdown can be disabled on reload. Original metadata remains immutable. This is an explicit challenge exception to ordinary reload's fresh-seed rule.
- Custom practice from a selection produces editable singleton operand groups using the existing exact-grid generator (division uses original divisor and quotient). Shares are split exactly. It opens setup for review and starts only when the user chooses Start. It is explicit manual practice, not an automated learning policy.
- Profiles include operation, operand size, answer length, negative/decimal notation, integer carry/borrow patterns, multiplication facts, operation transitions, removed digits and revision positions. Show valid-completion sample counts and timing components; sparse samples are descriptive.
- User labels (`mistyped`, `recalculated`, `unsure`, `unlabelled`) live in an independent revision-checked SQLite sidecar. Only ended-session questions can be labelled. Labels are user reports, never classifier ground truth. Concurrent stale writes fail. JSON/CSV exports include labels, challenge provenance and interaction data; confirmed session deletion also removes its labels.
