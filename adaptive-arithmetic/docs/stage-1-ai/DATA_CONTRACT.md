# Stage 1 data contract

Status: Complete local Stage 1 platform implemented, verified, and accepted by the user on 2026-10-23 (D-023). Detailed authoritative contracts are [CUSTOM_PRACTICE.md](CUSTOM_PRACTICE.md), [TIMING_EXPORTS.md](TIMING_EXPORTS.md), and [PLATFORM.md](PLATFORM.md).

Each session retains its original full configuration independently of presets; exact arithmetic values are decimal strings and raw observations are ordered, append-only and reconstructable. New sessions record mode/content as well as seed/generator/policy/measurement. Legacy mode/content/measurement remain nullable and unknown, never inferred from similar ranges or relabelled.

The sole backend derive_session supplies question records and timing summaries for results, history, graphs and exports. Correct-answer time is acceptance minus render-commit presentation, first-input is first field change minus presentation, and unfinished duration is observed duration with an explicit lower-bound flag when actual end is unknown. Raw precision is retained; UI seconds have two decimals. Edits are not wrong attempts and no accuracy percentage is invented. Render commit is not physical screen presentation; intervals include input and corrections.

Malformed ordering/identities, exact arithmetic, accepted strings, or content/provenance retain raw events and quality warnings while invalid affected timing values remain null. Derived identities normalize unsupported raw values to null. Legacy omitted accepted-input text can retain usable timing, with explicit uncertified metadata. Exact rational content checks do not round large custom products.

Decimal lexical rules are explicit and shared: trim only ECMAScript WhiteSpace/LineTerminator code points (including U+FEFF), then accept ASCII digits with an optional sign/plain decimal point. Python-only whitespace, internal whitespace, Unicode digits, exponents and separators remain invalid. Browser parsing, API decimal configuration validation, exact content/provenance, timing acceptance and comparison eligibility use this same rule; raw strings are never rewritten. Whole-second duration retains its separate ASCII-integer grammar.

Malformed input values or unsupported indices invalidate that question's timing interval. Missing/unknown/stale current-question references and clock/sequence damage taint the current unfinished and later intervals; independently completed earlier intervals survive later damage. A malformed raw field event cannot establish first-input timing. All derived aggregates, including partial-observation graphs, consume these same null-filtered intervals. Legacy omitted acceptance text remains usable only when the interval is otherwise valid.

Score counts observed acceptances; partial/inconsistent runs remain inspectable but are not full comparable scores. Full timed comparisons require known complete timeout, current provenance, consistent records and matching immutable content. One canonical full config + mode/content/generator/policy/measurement hash defines each cohort; names/IDs remain conservatively separate. Optional partial observations never enter full-run chronology. Histogram/operation/group/sample definitions are in PLATFORM; all aggregates consume retained derived questions.

Analytics additionally returns `fullRunStatistics`: `runCount`, nullable `meanScore`/`medianScore`, `answerSummary` using the existing question-summary shape, and `runTiming` containing `contributingRunCount`, `meanRunMeanMs`, `medianRunMeanMs`, `meanRunMedianMs`, `medianRunMedianMs`. D-026 adds nullable `bestScore`, `recentMeanScore`, `previousMeanScore`, `recentScoreDifference`, plus `recentRunCount`/`previousRunCount`. The two newest-first eligible score blocks contain up to ten runs each; the signed difference is recent mean minus previous mean in questions/run, null without both blocks. These statistics always use eligible full runs in the selected cohort/date range. Score zero is included; runs with no valid timing are omitted only from run-timing statistics. Empty numeric aggregates are null. The analytics endpoint's `totalSavedSessionCount` describes the unfiltered snapshot so the UI distinguishes no history from no date matches. `eligibleOnly` filters history before totals/paging and defaults false at the API; the UI explicitly defaults true. Raw observations and existing measurement versions are unchanged.

D-026 adds nullable SQLite `creation_key` with a unique partial index. Optional POST `creationKey` identifies one retained session-creation operation; matching retries return its original ID, conflicting valid payloads return 409. No-key clients keep existing behavior. Browser creation journals preserve the original config, seed and versions before network work, remain owned through a failed attempt, and are recovered only after ownership is available. The empty observation journal is installed before retiring creation metadata. No question presentation or known end timestamp is invented by recovery. This protocol metadata is separate from research observations; existing session and event columns keep their values.

The reload restart marker is per-tab sessionStorage metadata, separate from shared observation journals. A replacement has a new identity/seed and its own immutable config with countdown false; remembered setup stays intact. Its creation does not alter the old run's events or infer missing end timing. [PLATFORM.md](PLATFORM.md#reload-during-practice) defines consumption and lifecycle rules.

Every read/list/analytics/export uses a consistent SQLite read snapshot through concurrent writes or deletes. JSON preserves sessions with no questions; CSV has one row per presentation, exact strings and JSON-encoded raw input fields. Nullable additive mode/content/score/cohort columns extend CSV. Empty history remains valid JSON/header-only CSV. Raw events and immutable configurations survive preset rename/update/deletion.

Observation append batches acquire an SQLite write transaction before checking immutable sequence contents. Concurrent identical appends succeed idempotently; disagreement is HTTP 409 and rolls back the entire batch, including inserted tails/status updates. Compatible longer logs survive regardless of arrival order.

Retention is indefinite until explicit deletion. Confirm one closed record or an exact closed-history preview; atomic deletion protects database-open/missing-terminal records and browser ownership/pending journals, retains presets/custom setup, and never silently includes arrivals after confirmation. Read surfaces have no recovery/end/remembered-setup mutations. No third-party tracking or cloud synchronization is present.

Deletion preview optionally uses the same mode/state/date/configuration/eligibility predicates as History before collecting all matching closed IDs; pagination is not a deletion boundary. Global and filtered actions have distinct confirmations. URL navigation preserves view/filter/detail state but never changes observations merely by reading. Run again is available only after terminal save and creates a fresh run with the same settings, whereas active reload explicitly disables countdown for its replacement.

This contract defines descriptive observations, not cognitive speed, causal effects, confidence or learning benefit. Stage 2 planning is open; its research and substantive implementation remain user-owned. [ACCEPTANCE.md](ACCEPTANCE.md) and [HANDOFF.md](HANDOFF.md) record actual verification and practical limits.
